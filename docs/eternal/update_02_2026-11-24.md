# Builder Update — Week 2: Automatic release is now actually automatic

📹 Week 2 video: https://www.loom.com/share/99c6d6aeabae4c3f925127dbae742e16

**Shipped this week**
- **Keeper bot.** It scans every tenancy and calls our permissionless `settle` the moment one is due: the landlord was silent through the claim window, the landlord approved release, or the DAO vote closed. Nobody presses a button. The keeper has no power over the money, because amounts and recipients are calculated by the program itself. If it ever stops, anyone (including the tenant) can trigger the same payout.
- **Agent-first yield split, 60/20/5/15** (tenant / landlord / letting agent / UltraRentz). It's stored as an on-chain setting, so it can change without a redeploy. Each tenancy has an optional agent; with no agent, the agent's share goes to the tenant. **Principal is never split.** Rounding dust goes to the tenant, so every token is accounted for.
- **Three end-to-end scenarios pass on Solana** (local validator):
  1. Dispute: landlord claims 300, jurors vote 150/200/300, and the landlord receives the lower-median award of 200 plus their yield share.
  2. Agent-onboarded deposit with a silent landlord: automatic refund, with the yield split four ways.
  3. One-click release: the tenant is paid immediately.
- 10 Rust unit tests cover the payout maths, including vault shortfalls and rounding.

**Decisions**
- **Customer = letting agents**, not individual landlords. One agent brings hundreds of deposits.
- **Revenue = per-tenancy fees from agents** as the base; the yield share is upside, not the business.
- **Ireland is the first real market**: the deposit protection scheme legislated in 2015 was never commenced. England stays a test market.

**Challenges**
- Designing a four-way split around an optional agent account without breaking settlement.
- Devnet faucet rate limits blocked our public deploy this week.
